# Current PEAR2 native execution subset. Cases cover returns, arithmetic,
# recursion, direct calls, conditionals, scalar externs, loop-carried mutable
# locals, nested functions, first-class closures, tuple/unit clause calls, heap
# allocation with indexed stores and loads, block scoping, and a free on a
# loop-exit join.
#
# Every line here is a claim that pear2/pear2c builds AND runs the fixture with
# the fixture's own declared `-- EXIT:` value. scripts/pie-diff.sh reads this
# file: a fixture listed here that pear2c rejects is ledgered as a defect, not
# as `expected-reject`. Add a line only when the differential ledger shows
# `verdict=match` and `spec=exit-ok` at all four tiers; remove one the moment it
# does not.
#
# The 2026-10-26 additions were taken from that ledger, not from a reading of
# the backend: 14 fixtures outside this list were already compiling, running and
# returning their declared exit code on pear2c at -O0..-O3, plus 3 new
# memory/mu fixtures (p124, p125, p130).
#
# Deliberate exceptions, each measured rather than assumed:
#   * p09_stdout_extern is ledgered `diverge-stdout`, not `match`, because
#     pear1c is the broken side there: it builds and exits 0 but putchar writes
#     nothing, while pear2c prints the declared `A`.
#   * p116/p117/p118 (first-class closures) are ledgered `diverge-exit`, not
#     `match`, for the same reason from the other direction: pear1c SIGSEGVs on
#     all three at every tier while pear2c returns their declared 42.
#     In all four cases the reference backend is the wrong side, so keeping the
#     entry asserts pear2c's behaviour is the correct one. The ledger's
#     per-backend `spec` column is what makes that legible.
#   * p129_ptr_offset_store is NOT here. Pointer arithmetic feeding an indexed
#     store (`let p = a + 2; p[1] = …`) is outside the PEAR 2 subset; it is
#     ledgered `expected-reject` at all four tiers.
